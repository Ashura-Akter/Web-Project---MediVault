HOW THE PAGE IS BUILT (order in medivaultpharmasist.php)  [READ]
-----------------------------------------------------------------
 head -> modals (add stock, confirmations, cancel, reject) -> common topbar ->
 sidebar -> main content -> footer (viewer modal + scripts).
The backend has already prepared all variables (active tab, KPI numbers,
notifications, medicine list) so these view files mostly just print them.

JavaScript roles  [MAP]
- core            general dashboard behaviour (open/close modals etc.)
- deadline_picker date/time picker for reservation deadlines
- live_search     calls ?suggest=1 and shows medicine suggestions while typing
- live_counts     calls ?counts=1 and refreshes the counters without reload
- rx_viewer       opens the prescription viewer


prescription_view.php - HTML PART  [READ]
-----------------------------------------
Dark page split in two columns (CSS grid, 1fr + 360px; stacks on screens under 880px).
LEFT  : an <iframe> showing the real prescription (src = same page with &raw=1).
RIGHT : OCR result panel:
   - header: reservation number + badges ("OCR ran" / "OCR unavailable",
     "Awaiting decision" or the current status)
   - red error box if OCR failed (pharmacist can still judge the image)
   - green list  "Detected in prescription"  (requested and found)
   - red list    "NOT found in prescription" (requested, not found)
   - orange list "Other medicines seen (not requested)"
   - red notice if OCR ran but recognised nothing
   - collapsible "View raw OCR text"
   - footer note: approve/reject from the Pending tab
All values are printed with htmlspecialchars() so text from OCR or the database
cannot inject HTML/JS (XSS protection).
The <script> at the bottom is empty on purpose: viewer is read-only.
